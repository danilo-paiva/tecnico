Ideias de Projetos para Banco de Dados
Introdução
Este documento apresenta dez ideias de projetos para a disciplina de Banco de Dados. Os projetos foram pensados para envolver modelagem de banco de dados, diagramas, criação do banco físico e realização de consultas SQL.
Todos os projetos deverão conter muitas tabelas relacionadas e diversas consultas utilizando SELECT. As consultas deverão ser feitas sem o uso de JOIN explícito e sem o uso de SUBSELECT.
1. Requisitos Obrigatórios do Projeto
Cada grupo deverá desenvolver um projeto completo de banco de dados contendo os seguintes itens:
1. Tema do sistema; 2. Descrição do problema; 3. Objetivo do sistema; 4. Regras de negócio; 5. Modelagem conceitual; 6. Modelagem lógica; 7. Diagramas feitos obrigatoriamente no draw.io; 8. Criação do banco de dados físico; 9. Criação das tabelas com chaves primárias e estrangeiras; 10. Inserção de dados fictícios; 11. Consultas SQL sem JOIN e sem SUBSELECT.
1
1.1. Modelagem Conceitual

A modelagem conceitual deverá representar as principais entidades do sistema, seus atri butos e relacionamentos.
Devem ser identificados: · Entidades; · Atributos; · Relacionamentos; · Cardinalidades; · Regras principais do domínio escolhido.
1.2. Modelagem Lógica
A modelagem lógica deverá transformar o modelo conceitual em uma estrutura de tabelas. Devem ser definidos: · Nome das tabelas; · Atributos de cada tabela; · Chaves primárias; · Chaves estrangeiras; · Relacionamentos; · Cardinalidades.
1.3. Diagramas no draw.io
Os diagramas deverão ser feitos obrigatoriamente no draw.io, também conhecido como diagrams.net.
Devem ser entregues: · Diagrama Entidade-Relacionamento; · Diagrama lógico das tabelas; · Relacionamentos com chaves primárias e estrangeiras; · Cardinalidades entre as entidades.

1.4. Criação do Banco de Dados Físico
Cada grupo deverá criar fisicamente o banco de dados usando SQL. O projeto deverá conter comandos como:
CREATE DATABASE nome_do_banco ; USE nome_do_banco ;
CREATE TABLE tabela ( id INT PRIMARY KEY AUTO_INCREMENT , campo VARCHAR (100) NOT NULL
);
As tabelas deverão conter:
· PRIMARY KEY; · FOREIGN KEY; · NOT NULL; · Tipos de dados adequados; · Relacionamentos entre tabelas.
1.5. Inserção de Dados
O grupo deverá inserir dados fictícios suficientes para testar o sistema. Exemplo:
INSERT INTO aluno ( nome , ra ) VALUES ('Joao Silva ', '12345 ');
Sugestão mínima de dados:
10 registros nas tabelas principais ; 5 registros nas tabelas intermediarias ; 20 registros em tabelas de movimentacao , como compra , pedido , presenca ou

pagamento .

1.6. Consultas SQL
O projeto deverá conter muitas consultas SQL. Sugestão: · 10 consultas simples; · 10 consultas com duas tabelas; · 10 consultas com três ou mais tabelas; · 5 consultas com filtros usando WHERE; · 5 consultas com ORDER BY; · 5 consultas com GROUP BY. As consultas deverão respeitar a seguinte regra: · Não usar JOIN; · Não usar SUBSELECT.

Listar participantes inscritos em eventos:
SELECT participante . nome , evento . nome , inscricao . data_inscricao FROM participante , evento , inscricao WHERE participante . id_participante = inscricao . id_participante AND evento . id_evento = inscricao . id_evento ;
Listar palestras com palestrantes e salas:

O grupo deverá entregar um arquivo .sql contendo: · CREATE DATABASE; · USE;

14. Conclusão
Os projetos apresentados permitem aplicar os principais conceitos de banco de dados, in cluindo modelagem conceitual, modelagem lógica, criação do banco físico, relacionamentos entre tabelas, chaves primárias, chaves estrangeiras e consultas SQL.

Além disso, a restrição de não utilizar JOIN nem SUBSELECT nas consultas estimula o estudante a compreender melhor os relacionamentos entre as tabelas utilizando condições no WHERE.
